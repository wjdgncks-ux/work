# 스레드 측정 설계

> 이 문서가 모든 자동화의 전제다. 여기 정의되지 않은 지표는 파이프라인에 넣지 않는다.

## 1. KPI 트리 — 조회수는 최종 KPI가 아니다

```
문의 건수 (최종 KPI)
  └─ 랜딩 전환율          ← 랜딩 개선 영역
      └─ 링크 클릭         ← CTA 설계 영역  [Threads Insights 제공]
          └─ 프로필 조회    ← 프로필/첫줄 영역 [Threads Insights 제공]
              └─ 조회수     ← 훅/포맷/시간 영역 [Threads Insights 제공]
```

**조회수는 4단계 아래의 선행지표다.** 조회수만 보고 포맷을 결정하면
"넓고 얕은 도달 → 문의 0건" 구조로 수렴한다.

각 단계의 통과율을 매주 기록한다. 병목이 어디인지 모른 채
콘텐츠 포맷만 바꾸는 것이 가장 흔한 낭비다.

| 구간 | 지표 | 건강 기준(초기 가설, 3개월 뒤 실측치로 교체) |
|---|---|---|
| 조회 → 프로필 | 프로필 조회율 | 1.0% 이상 |
| 프로필 → 링크 | 링크 클릭률 | 5% 이상 |
| 링크 → 문의 | 랜딩 전환율 | 2% 이상 |

## 2. 수집 가능 / 불가능 경계

| 데이터 | 공식 API | 방법 |
|---|---|---|
| 내 게시물 조회수·좋아요·답글·리포스트·인용 | **가능** | `GET /{media-id}/insights` |
| 내 계정 팔로워·프로필조회·링크클릭 | **가능** | `GET /{user-id}/threads_insights` |
| **타인 게시물 조회수** | **불가능** | insights는 본인 미디어 한정 |
| 타인 게시물 텍스트·퍼머링크 | 제한적 가능 | `keyword_search` (App Review + 데모 필요) |

근거: [Meta — Keyword Search](https://developers.facebook.com/docs/threads/keyword-search/),
[Sendible — Threads Insights 2026](https://www.sendible.com/insights/threads-insights)

**결론: "조회수 1만 이상 자동 수집"은 불가능.**
타인 게시물은 사람이 퍼머링크 + 육안 조회수를 `swipe.jsonl`에 넣는다(하루 3분).
학습 루프의 본체는 타인 글이 아니라 **내 계정 실측 데이터**다.

## 3. 판정 규칙 — 이걸 안 지키면 전부 점(占)이다

1. **중앙값으로 비교한다.** 평균 금지. 바이럴 1건이 평균을 3배로 왜곡한다.
2. **n ≥ 20.** 같은 포맷 20건 미만이면 `analyze.py`가 "판정보류"를 출력한다.
3. **대조군 필수.** 새 포맷을 테스트할 때 기존 포맷을 같은 기간·같은 시간대에 병행 발행한다(`is_control: true`).
4. **72시간 기준 스냅샷으로 비교한다.** 게시 후 경과시간이 다른 글을 섞어 비교하지 않는다.
5. **초기 속도를 따로 본다.** `views@1h`가 최종 도달을 좌우한다는 것이 업계 공통 관찰이므로
   1h / 24h / 72h 세 시점을 모두 수집한다. (단 Meta 공식 발표 아님 — 가설로 취급)

## 4. UTM 규칙 (고정)

```
https://<랜딩>/?utm_source=threads
                &utm_medium=organic
                &utm_campaign=th-YYYYMMDD-NNN   # 게시물 1건 = 캠페인 1개
                &utm_content=<account_key>       # huchan_main | eggglobal
```

- **게시물마다 다른 URL을 쓴다.** 계정 단위 링크 클릭만으로는 어떤 글이 리드를 만들었는지 영원히 모른다.
- 스레드 전용 랜딩을 분리한다. 다른 채널과 섞이면 전환율 해석이 불가능해진다.
- 문의 폼에 `utm_campaign` 히든 필드를 심는다. 이게 있어야 KPI 트리 맨 위가 닫힌다.

## 5. 실험 단위

한 번에 **변수 하나만** 바꾼다. 훅과 길이를 동시에 바꾸면 원인을 분리할 수 없다.

```
exp-001  훅 유형      : contrarian vs case_number   (각 20건)
exp-002  발행 시간대  : 08시 vs 21시                 (각 20건)
exp-003  CTA          : reply_bait vs link          (각 20건)
```

실험 1건당 최소 4주. 그 전에 결론 내리지 않는다.
