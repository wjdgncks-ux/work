# 훅 분류 체계

`posts.jsonl` / `swipe.jsonl` 의 `hook_type` 은 반드시 이 표의 값만 쓴다.
분류가 흔들리면 analyze.py 의 비교가 전부 무의미해진다.

| 값 | 구조 | 첫 줄 예시 |
|---|---|---|
| `contrarian` | 통념 반박 | "리뷰 많은 집이 매출 높다는 거, 틀렸습니다." |
| `case_number` | 구체 수치 사례 | "문의 3건이던 매장이 8주 만에 41건 됐습니다." |
| `confession` | 실패·손실 고백 | "작년에 400만원 환불했습니다." |
| `question` | 직접 질문 | "대행사 견적서에서 이 항목 보신 적 있나요?" |
| `list_promise` | 목록 예고 | "9년간 본 망하는 매장의 공통점 3가지" |
| `insider` | 내부 관행 공개 | "대행사끼리는 이 키워드를 '깡통'이라 부릅니다." |
| `cost_reveal` | 원가·비용 공개 | "체험단 1건 실제 원가입니다." |
| `rebuttal_self` | 자기 반박 | "3년 전 제가 쓴 글, 지금 보면 틀렸습니다." |

## 훅 작성 규칙

1. **첫 줄에 결론을 넣는다.** 스레드 미리보기는 첫 줄만 보인다. 배경 설명은 2번째 줄부터.
2. **완충어 금지.** "~인 것 같습니다" → "~입니다". 근거는 본문에서 댄다.
3. **숫자는 앞쪽에.** 460, 2,900, 0.1% 는 3번째 줄 안에 들어가야 읽힌다.
4. **질문으로 끝낸다.** 답글이 초기 확산을 만든다는 것이 업계 공통 관찰이다.
   (Meta 공식 발표는 아니므로 가설로 취급하되, 비용이 0이므로 기본값으로 채택)
5. **훅과 본문이 어긋나면 폐기한다.** 낚시는 도달은 얻고 신뢰를 잃는다 —
   대행사 계정에서는 순손실이다.

## 새 훅 유형을 추가할 때

임의로 늘리지 않는다. 같은 구조가 `swipe.jsonl` 에 **5건 이상** 관찰된 뒤에만
이 표에 추가하고, 기존 데이터의 재분류 여부를 함께 기록한다.
