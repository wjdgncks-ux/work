# 스레드 게시물 기획·생성

이 스킬은 **초안 생성기**다. 사람 검수 없는 자동 발행을 전제하지 않는다.
출력은 항상 `drafts/queue/` 에 저장하고, `drafts/approved/` 로는 절대 직접 쓰지 않는다.

## 절차 (이 순서 고정)

### 1. 계정 선택

| 계정 키 | 정체 | 역할 | 문체 |
|---|---|---|---|
| `huchan_main` | 정후찬 개인 | **도달** — 신규 유입 | 단정형, 자기노출, 업계의 불편한 진실 |
| `eggglobal` | 에그글로벌 브랜드 | **신뢰·전환** — 문의 수납 | 사례·수치·실행법, 차분함 |

지정이 없으면 **주제로 판단한다**: 관점·경험·반박 → `huchan_main` / 사례·방법론·실적 → `eggglobal`.
상세 정의는 `references/personas.md`.

**금지 — 예외 없음**: 두 계정이 서로 독립된 제3자인 척 대립·논쟁·동조하는 구성.
동일인이 통제하는 복수 계정으로 여론을 만드는 것은 Meta가 Inauthentic Behavior로 규정해
네트워크 단위로 계정을 삭제하는 유형이다
(https://transparency.meta.com/policies/community-standards/inauthentic-behavior/).
대립 구조가 필요하면 아래 셋 중 하나만 쓴다.
- **실존 2인 대립**: 정후찬 vs 강도한 이사 — 실제 관점 차이만, 양쪽 다 실명
- **자기 반박**: "3년 전 나는 X라고 했다. 틀렸다"
- **공개 상호언급**: 두 계정이 같은 운영 주체임을 숨기지 않고 서로 태그

### 2. 실측 데이터 참조 (있을 때만)

`data/posts.jsonl` + `data/metrics.jsonl` 이 있으면 먼저 확인한다:

```
python3 scripts/analyze.py --by hook_type --at 72 --account <계정키>
```

- `판정가능`(n≥20) 그룹이 있으면 **상위 훅 유형을 우선 채택**한다.
- 전부 `판정보류`면 성과 데이터를 근거로 삼지 말고, 훅을 **분산**해서 표본을 쌓는다.
  이 경우 초안 3안의 훅 유형을 서로 다르게 낸다.
- 데이터가 없으면 이 단계를 건너뛰되, **"근거 데이터 없음 — 표본 축적용"** 이라고 출력에 명시한다.

부족한 표본으로 패턴을 단정하지 않는다. 판정 규칙은 `docs/measurement-design.md`.

### 3. 훅 설계

`references/hooks.md` 의 분류 체계에서 고른다. 훅은 **첫 1줄**이다.
스레드는 첫 줄만 미리보기에 노출되므로, 첫 줄이 나머지 전부보다 중요하다.

### 4. 본문 작성 제약

| 항목 | 규칙 |
|---|---|
| 길이 | 500자 이내(API 상한). 권장 150~350자 |
| 문단 | 2~3줄마다 개행. 벽돌 금지 |
| 해시태그 | 0~1개. 스레드는 해시태그 채널이 아니다 |
| 링크 | 본문에 직접 링크는 도달을 떨어뜨린다 — 첫 답글로 분리 |
| CTA | 게시물당 1개. `reply_bait`(질문형)를 기본으로 |
| UTM | 링크가 있으면 `th-YYYYMMDD-NNN` 형식 필수 |

### 5. 권위 근거 — 검증된 것만

**기본값(정후찬)**: 9년, 460개 기업, 2,900건 캠페인, 환불률 0.1% 미만.

**강도한 이사는 퍼포먼스 마케팅 주제에만**, 아래 수치만:
컨버스 뮬 ROAS 1,700% / CPA 4천원 / 전체 판매량 20% 이상 기여,
더 네이키드 오브젝트 ROAS 최대 800% / CVR 4%→12%.

**절대 금지(미검증)**: 300억 집행, 100개사 총괄, 3,000만 회 노출, 15배 매출 성장,
카테고리 1위 월매출 3억, 50만 다운로드, CAC 60% 절감.
초안에 들어가려 하면 자동 제거하고 사용자에게 알린다.

**실존 클라이언트명은 초안에 넣지 않는다.** 업종+규모로만 익명화한다.

### 6. 컴플라이언스 필터

주제가 병원·화장품·건기식에 닿으면 `references/compliance.md` 를 적용한다.
확실치 않은 법 조항은 추측하지 말고 "국가법령정보센터(law.go.kr) 확인 필요"로 표시한다.

### 7. 출력 형식

**3안을 낸다.** 훅 유형을 각각 다르게 해서 A/B 표본이 쌓이게 한다.
각 안을 `drafts/queue/YYYY-MM-DD-NNN-<hook_type>.md` 로 저장한다:

```
---
account: huchan_main
hook_type: contrarian
format: single
topic: agency_truth
cta_type: reply_bait
has_number: true
has_case: false
experiment_id: exp-001
is_control: false
utm_campaign: th-20260914-001
---
본문
```

### 8. 검수 체크리스트 동봉 (매번 필수)

```
□ 미검증 수치(300억·100개사 등)가 없는가
□ 실존 클라이언트명이 없는가
□ 컴플라이언스 위반 표현(완치·최초·100% 보장)이 없는가
□ 500자 이내인가 / 첫 줄만으로 클릭이 되는가
□ 두 계정 간 가짜 대립 구성이 아닌가
□ UTM이 게시물 고유값으로 들어갔는가
□ 사람이 직접 읽고 approved/ 로 옮겼는가   ← 이 항목 없이는 발행 금지
```

## 원칙

- 조회수가 목표가 아니다. **문의가 목표**다. 조회수는 4단계 아래의 선행지표다.
- 데이터가 부족하면 "부족하다"고 말한다. 패턴을 지어내지 않는다.
- 초안 채택률이 3주 연속 안정되기 전까지 발행 자동화 범위를 넓히지 않는다.
